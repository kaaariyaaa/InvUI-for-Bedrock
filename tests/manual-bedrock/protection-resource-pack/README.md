# アイテム操作抑制プローブ（単体実験用 RP）

`VirtualContainer` を含むチェスト系画面の**コンテナ側グリッド全体**に、入力を受け止める透明なボタン（以下「ブロッカー」）を重ね、**通常クリック・シフト相当・ドラッグ・ドロップなどのアイテム操作を JSON UI だけで止められるか**を目視で観察する、使い捨て Resource Pack です。

> [!WARNING]
> - **これは保護を提供しない実験用パックです。** アイテム保護、入力ブリッジ、クリック通知、`InventoryLink`、Script API 連携は一切含みません。ブロッカーは押下を `button.invui_protection_blocked` という**誰も処理しない ID**へ流すだけで、どこにも通知しません。**左記の未実装部分の代わりにこのパックを使わないでください。**
> - **実機未検証。** パックの読み込み、`modifications` の適用、ブロッカーがスロットより上に描画されること、入力を受け取ること、アイテム操作が止まることのいずれも検証していません。**この実験で確認する対象そのものです。**
> - **未保証。** 対象のゲーム版・プラットフォーム・画面サイズ・UI スケール・言語によって挙動は変わります。結果をバージョンをまたいで流用しないでください。`manifest.json` の `min_engine_version` は `[1, 26, 70]` の仮置きです。
> - **使い捨てワールド専用。本番ワールド・配布用ワールド・共有サーバー・通常プレイのワールドでは有効化しないでください。** 試験後はワールドごと破棄するか、パックを無効化して削除してください。
> - **通常のチェスト系画面にも作用し、操作を妨げる可能性があります。** ブロッカーはバニラの `chest` / `pocket_containers` パネル定義へ差し込むため、通常のチェスト・エンダーチェスト・シュルカーボックス・樽、ポケット UI ではホッパー等でもコンテナ側の操作が止まる可能性があります（実機未検証）。**このパックを有効にしたワールドで「通常チェストの基準確認」を合格にできません。** 基準確認はパックを無効にした状態で別に行ってください。
> - **通常ワールドのチェストを変更する実装ではありません。** このディレクトリの外（`resource_pack/`、コア、CLI の出力）には何も追加しません。通常ワールドへ配布・導入する前提の成果物ではありません。有効化したワールドでのみ作用します。
> - **`chest_screen.json` を同梱・上書きしません。** 既存ファイルへ `modifications` で差し込むだけです。
> - **スロット単位の部分一致はできません。** 表示専用スロットだけ、ボタンスロットだけを止める検証はできません。コンテナ側グリッド全体を 1 枚のボタンで覆います。プレイヤーインベントリ側・ホットバーは覆いません。
> - **InvUI 専用画面への限定はできません。** 画面タイトル等での識別は実装していません。ブロッカーは通常チェストに作用する可能性があり、`VirtualContainer` にも表示されるかは未確認です。ラベルが出ただけでは「InvUI 専用画面に適用できた」とは言えません。
> - **陰性（アイテムが動かない）だけでは合格にしません。** パック未適用、`modifications` 非対応、ブロッカーが下に隠れた、別の要因で操作できなかった、などを区別する必要があります。下記「判定」のとおり、**緑ラベル**と**赤いホバー/押下表示**を陽性対照として併用してください。
> - **アイテムを持ち出せた場合は即時中止**し、パックを無効化してください。表示専用アイテムや貴重品は使わないでください。コア側には「取り出し＋再描画による複製」の既知リスクがあり、このプローブはそれを検証・防止しません。

## 何をするか

バニラ `chest_screen.json` / `pocket_containers.json` のパネルへ、次の 2 つを `insert_back` で差し込みます。

1. **陽性対照ラベル**（緑）: パックが読み込まれ、対象パネルへ差し込みが効いたことの手がかり。
2. **ブロッカー**（透明な `button`）: コンテナ側グリッドとほぼ同じ位置・サイズに重ねる。ポインタが乗ると赤く色づき、押すとより濃く色づく。押下は `button.invui_protection_blocked` へ流れ、何も起きない。

| ファイル | 名前空間 | 差し込み先 | 差し込むもの |
|---|---|---|---|
| `ui/invui_protection_chest.json` | `chest` | `small_chest_panel_top_half`, `large_chest_panel_top_half` | 緑ラベル＋グリッド大のブロッカー |
| `ui/invui_protection_pocket.json` | `pocket_containers` | `panel` | 緑ラベル＋コンテナ側半分（右半分）のブロッカー |
| `ui/invui_protection.json` | `invui_protection` | 定義のみ | ラベル 2 種とブロッカー 1 種 |

デスクトップ側の座標はバニラのグリッド配置に合わせています（小: `offset [7, 9]`, `size [162, 54]` / 大: `offset [7, 10]`, `size [162, 108]`）。ポケット側は右半分（`anchor_from: top_middle`, `anchor_to: top_left`, `offset [0, 27]`, `size ["50%", "100%-27px"]`）を覆います。**ポケット側は実際のグリッドより広く、余白とスクロールバーも覆います**（レイアウトを厳密に切り出すほどの根拠が samples から組めなかったための単純化です）。

```
manifest.json                         resources モジュール
ui/_ui_defs.json                      上記 3 ファイルの登録
ui/invui_protection.json              ラベルとブロッカーの定義
ui/invui_protection_chest.json        chest 名前空間への modifications
ui/invui_protection_pocket.json       pocket_containers 名前空間への modifications
check.mjs                             JSON 構造チェック（実機の代替ではない）
```

## 根拠と限界

参照した公式 `bedrock-samples` のタグは **`v1.26.70.23-preview`**（commit `430142679bb7daf3160671f06ab32ea433be1e1d`）です。UI 構造の参照元であり、実行に必要なゲーム版ではありません。

| 参照元 | 確認した内容 | このパックでの使い方 |
|---|---|---|
| [`ui/chest_screen.json`](https://github.com/Mojang/bedrock-samples/blob/v1.26.70.23-preview/resource_pack/ui/chest_screen.json) | `small_chest_grid` / `large_chest_grid` の位置・サイズ、`chest_grid_item@common.container_item`、パネル階層 | グリッドに重ねる座標・サイズの根拠 |
| [`ui/ui_common.json`](https://github.com/Mojang/bedrock-samples/blob/v1.26.70.23-preview/resource_pack/ui/ui_common.json) | `container_item` が `$button_ref`（既定 `common.container_slot_button_prototype`）のボタンを子に持つ。その `button_mappings` が `button.container_take_all_place_all` / `button.container_take_half_place_one` / `button.container_auto_place` / `button.drop_one` / `button.drop_all` / `button.coalesce_stack` などを発火する | **スロット操作が JSON UI のボタン経由で発火する**という前提の根拠。ブロッカーは同じ入力 ID をすべて自作の no-op ID へ付け替える |
| [`ui/persona_popups.json`](https://github.com/Mojang/bedrock-samples/blob/v1.26.70.23-preview/resource_pack/ui/persona_popups.json) | `modal_window_input_blocker`（全面イメージ） | 全面の入力ブロッカーというパターンの根拠 |
| [`ui/persona_cast_character_screen.json`](https://github.com/Mojang/bedrock-samples/blob/v1.26.70.23-preview/resource_pack/ui/persona_cast_character_screen.json) | `common_background_blocker` が全面 `button` を子に持ち、`button.menu_select` / `button.menu_ok` をマッピングして入力を止める | **全面ボタンで下の入力を遮る**パターンの根拠。ただしこれはモーダルポップアップ内での用法であり、モーダル状態そのものが遮断に寄与している可能性を排除できない |
| [`ui/pocket_containers.json`](https://github.com/Mojang/bedrock-samples/blob/v1.26.70.23-preview/resource_pack/ui/pocket_containers.json) | ポケット側 `panel` の左右分割、`half_screen`、`inventory_grid` | ポケット側ブロッカーの基準 |
| [Bedrock Wiki — Hardcoded Button IDs](https://wiki.bedrock.dev/json-ui/json-ui-documentation) | `button.container_take_all_place_all` / `button.container_take_half_place_one` / `button.container_auto_place` / `button.coalesce_stack` / `button.drop_one` / `button.drop_all` は**ゲーム側が処理する hardcoded button ID** | これらを JSON UI 側で受け止めれば動作を止められる、という**仮説**の根拠。成立するかは未検証 |

既存プローブの作法（[`button-send-resource-pack/`](../button-send-resource-pack/README.md)、[`chest-resource-pack/`](../chest-resource-pack/README.md)）に合わせ、`modifications` の `insert_back` と緑ラベルの陽性対照、`chest_screen.json` を同梱しない構成を踏襲しています。

### 根拠が届いていない部分（正直な限界）

- **ブロッカーが下のスロットへの入力を実際に奪えるかは、samples からは証明できません。** バニラのスロット操作が JSON UI のヒットテストに従うなら止まりますが、ゲーム側がポインタ位置からスロットを直接解決している場合は、上にボタンを重ねても操作が通る可能性があります。**このプローブの中心的な不確実性です。**
- `common_background_blocker` はモーダルポップアップ内の全面ボタンであり、モーダルでないチェスト画面に同じ効果があるとは限りません。
- **コントローラーは特に弱い想定です。** ブロッカーは 1 つの大きなフォーカス対象にすぎず、下にあるスロットボタンのフォーカス対象を除去できません。フォーカスが下のスロットへ移れば、A 押下で操作が通る可能性があります。コントローラーで止まらなくても、PC の結果を否定するものではありません（false negative の可能性）。
- **ドラッグ・ドロップ・ダブルクリック相当が JSON UI のボタンマッピング経由かは確認していません。** ブロッカーはこれらも no-op へ割り当てていますが、ゲーム側が別経路で処理すれば通ります。
- **画面識別をしていません。** InvUI 専用画面だけに適用する方法（設計書 10.7）は未確定であり、このパックは通常チェストにも同じブロッカーを出します。

## 手順

1. 使い捨てワールドを複製し、ワールドとパックのバックアップを取る。
2. **パックを無効にした状態で**、通常チェストのアイテム移動を確認する（基準）。`VirtualContainer` を使う場合は、別途 [`../probe/`](../probe/README.md) の raw probe で `!invui open 27` を実行できる状態にする。**テスト用アダプタや `Window.open()` を直接許可するコードは使わない**（現行コアは既定で拒否）。
3. このディレクトリを `development_resource_packs/` に置き、ワールドで**このパックだけ**を有効化する。他の Resource Pack（特に `button-send-resource-pack/`、`chest-resource-pack/`、`data-driven-resource-pack/`）と併用しない。Behavior Pack は不要（`VirtualContainer` を開く場合のみ raw probe）。
4. 使い捨ての棒・紙などをコンテナへ数種類入れておく。**カーソル上を空にし、サバイバルで行う。**
5. 通常のチェストを開く。緑ラベルが出るか、末尾が `desktop` か `pocket` かを記録する。ラベルが出なければ、パック未適用・`modifications` 非対応・差し込み先の変更などの可能性があるため、以降の結果を使わない。
6. コンテナ側グリッド上でポインタを動かし、**赤い色づき**が出るか確認する。出ない場合、ブロッカーがスロットより下・画面外・クリップされている可能性がある。**この場合の陰性は判定不能**として記録する。
7. 次の操作を 1 つずつ試し、**そのたびにコンテナ内・プレイヤーインベントリ・カーソル上の個数を突き合わせる**。
   - コンテナのアイテムをクリックで取る
   - プレイヤーインベントリからコンテナへ置く
   - シフトクリック相当（クイックムーブ）
   - ダブルクリック相当（同種まとめ）
   - コンテナ内でスロット間移動、インベントリへドラッグ
   - ドロップ（Q 相当）
   - タッチの長押し・ドラッグ、コントローラーのフォーカス移動＋決定
8. `VirtualContainer` の画面でも 4〜7 を繰り返す（開ける場合のみ）。画面サイズ・UI スケール・言語・入力方式を記録する。
9. パックを無効化し、**通常のチェストで移動が従来どおり動くこと**を再確認する。動かなければ即時中止し、ワールドをバックアップから復元する。

## 判定

| 観察 | 解釈（断定ではない） |
|---|---|
| 緑ラベルが出ない | パック未適用・画面違い・見切れなどを区別できない。以降の陰性は判定に使えない |
| 緑ラベルは出るが、グリッド上で赤い色づきが出ない | ブロッカーが入力を受けていない/見えていない。**判定不能**。スロット操作が止まっても「ブロッカーで止めた」証拠にならない |
| 赤い色づきが出て、クリックしてもアイテムが動かない | その入力方式・その画面では**この手法で抑制できた可能性**。ただし全操作・全スロット・全画面の証明ではない |
| 赤い色づきが出るのにアイテムが動く | **ブロッカーでは止められない**（JSON UI の上重ねだけでは不十分）。保護をこの方式で実装しない判断材料になる |
| 一部の操作だけ止まる | 部分抑制。**保護として扱わない**。操作ごとに記録する |
| アイテムが増減・複製した | **即時中止**。ワールドを破棄/復元する |
| 通常チェストの移動が壊れた | このパックの意図した作用。通常プレイに戻すためパックを無効化する。試験中なら記録して継続可 |

ラベルはグリッドの外（小: `y=66`、大: `y=120`）に置いていますが、UI スケールや言語次第で見切れる可能性があります。赤い色づきは `hover` / `pressed` の画像で、PC ではホバー、タッチでは押下時に見えます。**コントローラーでは赤い色づきが出ない**ため、陽性対照が弱くなります。

### false positive / false negative

- **false positive（保護できたと誤認する）**
  - 空スロットや、カーソルに既にアイテムを持った状態で試すと「動かない」ように見える。スロットを埋め、カーソルを空にしてから試す。
  - 表示専用アイテムがそもそも操作対象でない、またはクリエイティブで挙動が異なる。サバイバルで使い捨てアイテムを使う。
  - 赤い色づきが出ないまま「動かない」場合、ブロッカーではなく別の要因（画面の不具合、アイテムの種類、UI の重なり）で動かなかった可能性がある。判定不能とする。
  - 緑ラベルだけを見て「InvUI 専用画面に適用できた」と誤認する。通常チェストにも出る。
- **false negative（止められるのに止まらなかったと誤認する）**
  - ブロッカーがスロットより下に描画されている、画面外・クリップされている（UI スケール・言語・解像度）。
  - バニラと異なるパネルを使う画面（例: `data_driven_container`）では、このパックの `modifications` が当たらない。
  - コントローラーのフォーカスが下のスロットへ移り、ブロッカーを経由せず操作される。
  - ポケット側のブロッカーが右半分を覆う単純化のため、実際のグリッドとずれて一部のスロットが露出する。
  - ドラッグ・ドロップなどが JSON UI を経由しない経路で処理される。
- **このプローブで確認できないこと**
  - スロット単位（表示専用 / ボタン / 通常）の選択的な抑制。
  - InvUI 専用画面だけへの適用。
  - クリックの Script API への通知、`InputBridge`、`!invui:` チャット通知。
  - アイテムの複製・消失が起きないこと（そもそも保護していない）。
  - 実際のゲーム版での `modifications` / レイヤー / 入力ヒットテストの仕様。

### 結果が陰性・判定不能だった場合に報告する観測

- 画面の種類（通常チェスト / `VirtualContainer` / その他）と、使用したパネル系統（desktop / pocket）。
- 緑ラベルの有無、赤いホバー/押下表示の有無。
- 操作ごとの結果（取る・置く・シフト・ダブル・ドラッグ・ドロップ・タッチ・コントローラー）。
- ゲーム版、`@minecraft/server` 版（`VirtualContainer` 使用時）、プラットフォーム、入力方式、画面サイズ、UI スケール、言語。
- 併用パックの有無（原則なし）。
- スクリーンショットまたはログ。再現手順。

### 陰性だった場合に次に検討する観測

- **赤い色づきが出るのにアイテムが動く**場合、JSON UI の上重ねだけでは操作を遮断できない、という結果として扱い、この方式の保護実装を採用しない。次は Script API 側（`VirtualContainerItemChange` など）で変更を観測できるか、観測できた場合に安全に巻き戻せるかの検証になる。ただし巻き戻しはアイテム消失・複製の危険を伴い、このプローブの範囲外である。
- **PC では止まるがコントローラーでは止まらない**場合、設計書 10.8 の「PC、タッチ、コントローラーで通常クリック相当の入力が成立する」を満たさない。入力方式ごとの結果を分けて記録し、合格にしない。
- **赤い色づきが出ない**場合、まずブロッカーの描画順・クリップ・`modifications` の適用可否を切り分ける。この状態の陰性は方式の可否の証拠にならない。

## このパックが提供しないもの

- **アイテム保護**: 表示専用アイテムの保護、移動制限、複製・消失の防止。
- **クリック通知 / InputBridge**: 押下は `button.invui_protection_blocked` に流れるだけで、Script API・Behavior Pack・チャットへは何も送りません。**InputBridge には接続していません。**
- **スロット単位の制御**: グリッド全体を 1 枚で覆うだけで、対象スロットを選べません。
- **画面識別**: InvUI 専用画面の判定。通常チェストにも作用します。
- **保証**: パックが読み込まれること、ブロッカーが描画・入力されること、アイテムが保護されること。

## 検査

```bash
node tests/manual-bedrock/protection-resource-pack/check.mjs
```

確認できるのは JSON の整合性だけです。manifest の警告文、`_ui_defs` の参照先、ラベルが `label` であること、ブロッカーが `button` でスロット系の入力だけを no-op へ流すこと、禁止した入力系 control・`bindings` / `collection_name` が混入していないこと、`chest` / `pocket_containers` の対象パネルへの `insert_back` と座標、`chest_screen.json` を同梱・登録していないこと、README に安全警告と出典が残っていることを `node:assert` で検証します。

確認できないこと:

- パックが読み込まれるか、ラベルとブロッカーが表示されるか。
- ブロッカーが入力を受け取り、アイテム操作を止めるか。
- 通常チェストへの影響の有無、アイテムの複製・消失、入力方式ごとの挙動。

## 片付け

試験後はワールドごと破棄するか、このパックを無効化・削除してください。**通常のチェストで移動が従来どおり動くことを再確認**し、結果を記録します。結果は [CHECKLIST.md](../CHECKLIST.md) の `PROT-*` に転記しますが、**このプローブの結果だけで `PROT-01`〜`PROT-04` を合格にしないでください**（グリッド全体の抑制しか見ておらず、スロット単位の保護・複製防止・InvUI 限定を確認していないため）。
