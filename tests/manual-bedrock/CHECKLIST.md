# 実機テスト合否チェックリスト

試験ごとにこのファイルをコピーして記入してください。手順の背景と安全上の注意は [README.md](README.md) を参照します。

> **未検証機能を「動作確認済み」にしないための記録です。** 現行コアの `Window.open()` は既定で実画面を開きます（実アダプタの `canOpenScreens = true`、`VirtualContainer.open()` を呼ぶ）。テスト用アダプタの注入は不要ですが、**この経路は実機未検証**で、表示アイテムは `setItem()` で置かれるだけで保護されません。取り出し＋再描画で複製、再描画の上書きで消失が起こり得ます。`setContainerAdapter()` で `canOpenScreens = false` のアダプタを渡した場合だけ `WindowOpenRejectedError` になります。
>
> Resource Pack の画面接続（`ui/invui_connect.json` / `ui/invui_connect_data_driven.json` → `data_driven_container` の `desktop_panel` / `pocket_panel`）は**変更中で適用可否は未検証**です。接続は警告ラベルと `invui_probe_root` を `insert_front` で、**透明ブロッカー**（`invui_connect_probe.grid_blocker`）を `insert_back` で差し込みます。`VirtualContainer` を特定できないため、通常のコンテナを含む同パネルの全画面に適用され得ます。**VirtualContainer 画面が同パネルを使っているかは未確定**です。ブロッカーは保護ではなく、覆った範囲では**ボタンや inventory slot も抑制し得る**一方、**プレイヤー側のインベントリ・ホットバーは覆わず、controller・タッチ入力の遮断を保証しません**。作業ツリーの `ui/_ui_defs.json` は接続 2 ファイルを登録済みですが、これは変更中の状態です。試験時点の実ファイルを確認して ENV-06 に記録し、「接続済み」「未接続」のどちらも既定事実として扱わないでください。`ENV-*` と `BASE-*` 以外は、実際に実施するまで「未実施」のまま残してください。実施は使い捨てワールドだけで行ってください。
>
> **raw probe とコアの試験は別物です。** [`probe/`](probe/README.md) の raw probe はコアもアダプタも使わず `world.virtualContainerManager` から `VirtualContainer` を直接開き、`VirtualContainer` 単体の表示・close reason・itemChange だけを確認します。DISP 以降のコア試験（`Window.open()` 経由のレイアウト・描画・保護）とは対象が違い、**相互に結果を流用できません**。どちらも未実施です。
>
> `button.send` を単独で観察する [`button-send-resource-pack/`](button-send-resource-pack/README.md) は**使い捨てワールド専用**の別キットです。クリック通知は未検証で、通知文字列を自動設定する仕組みはなく、入力抑制・アイテム保護もありません。**他の Resource Pack との併用は禁止**です。このキットを導入しただけでは `CLICK-*` を実施済みにしないでください。

## C. アイテム保護（表示専用・ボタン用スロット）

**表示専用アイテムが 1 つでも持ち出せたら不合格。** 現行コアは表示アイテムを `setItem()` で置くだけで保護がないため、取り出し＋再描画による複製、再描画による消失も試します。画面からの変更は `WindowItemChangeDangerError` として通知され再描画停止・close 要求が行われますが、`after` イベントのため保護ではなく、**通知が来てもアイテムは戻りません**。通知の有無や close の成否を合格根拠にしないでください。合格するまで D へ進まない。

> **既定接続の透明ブロッカー（`invui_connect_probe.grid_blocker`）は保護ではありません。** コンテナ側グリッド付近を覆い、スロット系入力を `button.invui_connect_blocked` へ流すだけで、受け側のスクリプトはありません。覆った範囲では表示専用スロットだけでなく**ボタンや inventory slot も押せなくなる可能性**があり、逆に**プレイヤー側のインベントリ・ホットバーは範囲外**です。controller のフォーカス移動、タッチの長押し・ドラッグ、JSON UI を経由しない操作の遮断は保証しません。赤いホバー・押下表示は入力を受けた手がかりにすぎません。**ブロッカーでアイテムが動かなかったことを `PROT-*` の合格にせず**、ボタン・inventory slot を巻き込んだか、プレイヤー側・controller・タッチで操作できたかを「根拠・メモ」に記録してください。アイテム保護の実装・検証は別途必要です。

| ID | 手順 | 合格条件 | 結果 | 根拠・メモ |
|---|---|---|---|---|
| PROT-01 | PC で表示専用アイテムをクリック、Shift クリック相当、ドラッグ、ダブルクリック相当、ドロップする | アイテムが移動・消滅・複製しない | | |
| PROT-02 | タッチでタップ、長押し、ドラッグ、ダブルタップ相当を行う | 同上 | | |
| PROT-03 | コントローラーでカーソルを合わせ、決定・ドラッグ相当・ドロップ相当を行う | 同上 | | |
| PROT-04 | 操作前後で保管領域と画面内の個数を数える | 合計個数が一致し、複製・消失がない | | |
| PROT-05 | ボタン用スロットと表示専用スロットを混ぜた画面で同様に操作する | ボタン以外のアイテムが動かない。ボタン押下でアイテムが消費されない | | |
| PROT-06 | 表示専用アイテムを取り出した後に、状態更新や `refresh()` で再描画させる | 同じアイテムが再設定されて複製しない。再描画でアイテムが消失しない。複製・消失したら即時中止 | | |

> 画面からの変更時に `WindowItemChangeDangerError` が通知されたか、通知後に close 要求が効いたかは「根拠・メモ」に記録します。通知は保護ではないため、通知が来たことだけを合格にしません。

## D. クリック通知

入力経路が利用可能な場合だけ実施します。現行コアにはクリック入力を実機イベントへつなぐ仕組みがなく、`button.send` → チャット通知は候補で、チェスト画面で成立するかは未確認です。Resource Pack の画面接続は変更中・適用可否未検証で、接続しただけでは通知は届きません。既定接続の透明ブロッカーは押下を `button.invui_connect_blocked` へ流すだけで、クリック通知を送りません。成立しない場合は「不合格」として記録し、別方式を検討します。

`button.send` の観察だけを行う場合は、[`button-send-resource-pack/`](button-send-resource-pack/README.md) を**使い捨てワールドで単独使用**します。このキットは陽性対照ラベルと押下用ボタンを差し込むだけで、**通知文字列を自動設定する仕組みはなく**、入力抑制・アイテム保護もありません。他の Resource Pack との併用は禁止です。ラベルやボタンが出たこと、押下で見た目が変わったことは、CLICK-* の合格ではありません。
